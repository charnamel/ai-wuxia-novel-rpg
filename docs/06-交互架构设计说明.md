# 交互架构设计说明

> AI 武侠互动 RPG 的当前交互与代码架构设计说明。

## 一、架构概览

玩家每输入一轮行动，主程序一次性调用剧情模型，把"剧情正文 + 状态更新"一并生成出来，随后再分发给各模块做程序化落盘。

```
玩家输入
   │
   ▼
┌─────────────────────────────────────┐
│ 主循环一轮剧情生成（单次 LLM 调用）    │
│  llm_call_common(主剧情模型)          │
│  · 输入：System Prompt + 分层上下文    │
│    + 玩家行动 + 特殊指令              │
│  · 输出（同一轮返回）：               │
│    剧情正文（带【本轮剧情】等标签）     │
│    + update_game_state 工具调用       │
└───────────────┬─────────────────────┘
                ▼
┌─────────────────────────────────────┐
│ 状态落盘（工具/正则/程序化多通道）      │
│  · update_game_state → 玩家/NPC/任务  │
│  · vitality_system → 气血/内力/伤势    │
│  · dice/战斗 特判 → DC 检定结论落地     │
│  · location_time → 时辰/天气/地点      │
│  · mainline_dynamic → 主线进度         │
└─────────────────────────────────────┘
```

核心思路：让大模型专心写剧情，状态变化交给"工具调用 + 程序化结算"双通道，避免 AI 顾了文笔顾不了数值。

***

## 二、主循环流程（main.py）

### 2.1 剧情生成

主循环调用 `llm_call_common`（[main.py L424-L466](file:///d:\code\NEW6\main.py#L424-L466)）做一轮生成（[main.py L4849-L4860](file:///d:\code\NEW6\main.py#L4849-L4860)）：

- 传入：`system_prompt`（含核心铁律、工具规则）+ 分层上下文 + 玩家本轮行动 + 需要的特殊指令；

- 返回：同一轮响应里同时带剧情正文与 `update_game_state` 工具调用；

- 思考模式按模型通过 `extra_body` 的 `thinking` 区分，只控制模型是否输出 reasoning。

### 2.2 分层上下文（L3 / L2 / L1）

每轮按记忆层级组装上下文，兼顾"即时承接"与"全局一致"：

- **L3-1 全局剧情脉络**：长期世界观、人物命运、已发生的重大事件；

- **L3-2 近期概要**：最近一段时间剧情摘要；

- **L2 交互日志**：近几十轮对话细节（当前块不足 10 轮时用上一块补足，避免边界突变）；

- **L1 即时场景锚点**：上一轮剧情末尾，供主循环无缝续写。

### 2.3 剧情正文解析

大模型正文按约定标签解析（[main.py L4895-L4912](file:///d:\code\NEW6\main.py#L4895-L4912)）：

- 【本轮剧情】【NPC状态变动】【道具/自身健康状态】【时间变更】【地点变更】【行动选项】【近期剧情记录】【任务进度】等；

- 行动选项从正文正则提取，前端渲染成按钮。

## 三、状态更新体系

状态改变走"工具优先 + 正则兜底 + 程序化主动"多通道：

1. **工具通道**：`update_game_state`（[main.py L3719-L3723](file:///d:\code\NEW6\main.py#L3719-L3723)）承载玩家属性、NPC 好感/关系/记忆、任务、声望、武功经验、小说节点等；
2. **正则兜底**：剧情里有明确伤势/死亡/气血描述但没走工具时，`vitality_system` 用正则补齐；
3. **程序化主动**：战斗特效、持续性状态（外伤/中毒等）由模块主动挂载/结算，优先于 AI 上报。

关键约定：

- **NPC 亡故/重伤**：`body_status` 主要由 HP 反推，`body_status_desc` 经 `sanitize_desc` 展示层过滤，保证剧情文字与 HP 状态一致、无"僵尸描述"；

- **禁止 AI 乱标亡故**：NPC 死亡只能由战斗结算或明确主线事件触发，普通剧情不得直接给"已故"。

***

## 四、骰子 DC 系统（可开关）

DC 系统是战斗数值的中枢，整体可一键关闭：

- **判定流程**：`ai_judge_dc_only` 用辅助小模型根据场景判难度(DC) → `resolve_check_v4` 掷 d20+修正对照 DC → 八档结果 → `judge_grade_v4` 生成约束文本，注入【!系统检定·必须遵循!】让剧情严格服从检定结论（但禁止出现"骰子/DC/d20"等游戏术语）。

- **三个来源的修正**：

  - 基础修正 = 整体境界查表（初学 -1 → 破碎虚空 +12）；

  - 武功加成 = 品阶加成 + 武功自身境界加成（2 境一档 0\~+7，瓶颈突破即晋档）；

  - 增幅 = 内功/轻功按品阶+境界折算百分比乘攻击总修正（轻功减半）。

- **环境/战术修正**：`environment_mod`（天时地利±4）、`situation_mod`（人和战况，带伤/负伤阈值 70% 触发）、`equipment_mod`（装备±1）。

- **开关**：Web 侧边栏「系统」组按钮 → 写 `.env` 的 `ENABLE_DICE_SYSTEM`（true/false，缺省自动补），即时生效无需重启。关闭后不掷骰、不弹检定面板，HP/MP 完全由 AI 文字裁定（vitality 约束仍在）。

- **关闭的影响**：伤害决策失去数值锚点，完全靠 AI 文字测算；DC 数据图表不展示。

***

## 五、战斗与状态系统

- **战斗模块**（`battle_system.py`）：多轮对战流程，每轮优先用战斗专用工具 `battle_settle_vitality`（仅 `vitality_change` 字段）结算气血内力，正则【体力结算】作兜底；战斗多轮回合的细节不全部塞进主上下文，只注入压缩的战斗摘要；

- **气血/内力**（`vitality_system.py`）：进程内结算，含自然恢复（每 5 轮 HP+10% MP+20%）、战斗后 MP 回 3%、`sanitize_desc` 伤势对齐；

- **持续性状态**：由 `data/effect_config.json` 定义（外伤/中毒等），`tick_effects` 每轮"发作广播 → 剩余回合-1 → 到期移除"，`apply_effect` 挂载、`mount_martial_effect_triggers` 战斗特效主动挂；1 轮状态当轮挂、当轮演、当轮结。

***

## 六、天气 / 时辰 / 地点（location\_time.py）

- 地点、时辰、天气、小说节点由 `location_time.py` 统一维护，每轮注入 L1 锚点；

- **天气**：单一更新逻辑——Web 端每 5 轮以 25% 概率从天气池换一个天气；天气池按 `player.json` 的 `novel` 参数（如"1755年秋"）匹配季节天气池（春夏秋冬各一套），匹配不上用统一池；

- **时辰**：必须是十二时辰标准值之一（子—亥），提示词约束 + 后端正则清洗，禁止带"三刻/略耗"等花字；

- **季节识别**：正则带年份兜底，匹配不上抓第一个"春夏秋冬"，无年份也能识别。

***

## 七、主线与任务系统

- **主线**（`mainline_dynamic.py`）：以约 89 个原著桥段的严格顺序推进为骨架（`data/mainline_catalog.json`），AI 只负责把"触发入口"适配到玩家当前场景，核心剧情/人物/内核遵循原著；

  - **手动**：「回归主线」→ `advance_mainline()`，有前置校验（进行中主线、近 3 轮冷却），不通过零 API 消耗返回；支持「选择主线/跳转主线 N」；

  - **自动**：进度积分制——普通行动每轮 +1、战斗结算 +5、手动回归主线 +8，累计满固定阈值 100（`MAJOR_PLOT_TRIGGER_POINT`）触发一次（触发后归零）。自动触发只注入【主线暗线牵引】：读取当前进度 X+1 号桥段，引导 AI 在当前场景自然埋一枚线索，不推进主线编号、不自动建任务，待玩家主动靠近再展开；玩家推进到 X+1 后，自动触发才顺延指向 X+2；

  - **进度模块化**：`init_progress / update_progress / check_and_consume_mainline_flag` 位于 `mainline_dynamic.py`，`main.py` 转发导入；

- **任务**（`task_manager.py`）：主任务/支线任务（`type=side`），支线仅在剧情自然涉及相关 NPC/情节时更新进度，没有独立的自动触发。

***

## 八、记忆与检索

- **多级记忆**：上下文 L1/L2/L3 之上，另有 NPC 记忆、章节摘要、世界设定等按需检索注入（`context_cache.json` 组织）；

- **世界书**（`worldbook`）：关键词子串匹配，<5ms 延迟、约 150KB 索引，本地实现、零 API 成本；

- **语义向量检索**：`local_vector_store.py` / `semantic_index.py` 本地 BGE-small 模型，向量走本地存储（`data/semantic_vectors.npy` + ids）。模型在后台线程加载、不阻塞游戏请求（失败快速返回空、自愈重试）；`ENABLE_SEMANTIC_SEARCH=true` 默认开启；

- **主动检索**（`active_cloud_retrieval.py`）：用小模型生成检索关键词再本地检索。

***

## 九、角色与成长

- **玩家**（`player_manager.py`）：境界体系 14 档（初学入门→破碎虚空）、武功经验、瓶颈系统（瓶颈重数 × 下一境经验差 × 系数、下限 10）、装备槽、年龄（自动同步）等；

- **NPC**（`data/npc_agents.json`）：人设、好感/关系、记忆、气血内力；已故角色从活跃集合剔除，杜绝"诈尸"出场；

- **加成规则外置**：`data/dice_rules.json`、`data/martial_arts_bonus.json`，支持热重载。

***

## 十、配置与部署

- **模型配置**：.env 中 `MAIN_LOOP_*`（主剧情模型可选 MiniMax-M3 / deepseek-v4-flash / glm-5.3-flash，`MAIN_LOOP_ACTIVE` 选组）；辅助小模型（DC 判定、信息提取等）独立配置；

- **主要开关**：`ENABLE_DICE_SYSTEM`（DC 开关）、`ENABLE_SEMANTIC_SEARCH`（语义检索）；

- **模型注意点**：GLM-5.3 需 `thinking.type='enabled'` + `reasoning_effort='low'`，且 `max_tokens≥5000`，不可用其 reasoning\_content 回灌剧情；

- **部署**：Linux Ubuntu + gunicorn，`--workers=1`（配 gthread/threads）防剧情异步错乱，`--timeout 120`；所有控制台清理屏逻辑按平台 `sys.platform=='win32'` 门控。
