| 上下文范围 | 仅L1场景+玩家输入 | 新增近期剧情摘要 | 上下文更完整 |

## 三、关键发现

### 3.1 剧情节点污染完全消除

v2中10个场景有8个被"萧半和/铁鹞堂"污染，v3中0个。

**v2示例**（Round 686 "不想走镖"）：
```
[剧情线索] 萧半和 病危 铁鹞堂  ← 完全无关
[人物] 飞马镖局 镖头            ← 相关
[地点] 飞马镖局 杭州            ← 相关
```

**v3示例**（同场景）：
```
[人物] 飞马镖局 镖头 师父 王    ← 精准
[地点] 飞马镖局 杭州 镖局        ← 精准
[剧情线索] 走镖 打杂 任务 飞马镖局 ← 精准
```

### 3.2 主动检索的检索范围（回答用户问题）

v3的思考prompt包含三个层次的信息：

1. **近期剧情摘要**：从 `context_cache.json` 的 `compressed_global_summary` 加载，覆盖全局剧情走向（~300字）
2. **上一轮剧情（L1）**：上一轮AI生成的剧情末尾（~300字）
3. **玩家本轮行动**：玩家原始输入

小模型基于这三个层次生成检索关键词，确保：
- 不会只看当前一句话（避免短文本盲区）
- 不会引入无关主线背景（避免污染）
- 能联想前几轮出现的NPC/武功/地点

### 3.3 主动检索的优势场景

**短文本场景**（Round 1176）：
- 玩家输入仅7字："师父，当然是……报官咯"
- 被动检索：1条（几乎找不到）
- 主动检索：17条（小模型联想到"报官 告状 缉捕 官府"）

**多维度场景**（Round 245）：
- 玩家问铁寨主名字和武功
- 被动检索：7条（只匹配"铁寨主"）
- 主动检索：23条（联想到铁雄+铁门闩刀法+铁门寨+袁依依+鸳鸯刀）
- 校验评分：8/10

### 3.4 主动检索的劣势场景

**宽泛匹配场景**（Round 686 "不想走镖"）：
- 主动检索找到15条，但校验评分仅2/10
- 原因：小模型联想了"飞马镖局 镖头"但命中了大量无关NPC（血刀老祖、商家堡等）
- 被动检索只找到2条但更精准

### 3.5 耗时分析

v3主动检索平均12.33s，构成：
- 小模型思考：4-7s
- 并行检索3组：3-5s（并行后大幅缩短）
- 二次校验：2-3s

对比v2的24.73s，耗时减半。主要来自：
1. 5组串行→3组并行（-10s）
2. WB max_chars从1500降到1000（-2s）
3. 去重减少后续处理量（-1s）

## 四、二次校验分析

### 4.1 成功案例

| 场景 | 评分 | 噪声维度 | 分析 |
|------|------|---------|------|
| Round 245 | 8/10 | 无 | 覆盖铁雄、铁门寨及鸳鸯刀线索 |
| Round 491 | 9/10 | 无 | 紧密围绕鸳鸯刀、萧家人物 |
| Round 686 | 2/10 | 剧情线索、地点 | 与玩家意愿关联弱 |
| Round 1911 | 5/10 | 地点、剧情线索 | 地点组未命中，人物组有效 |

### 4.2 失败原因

6/10场景校验失败，原因是 DeepSeek v4-flash 的 thinking 模式导致模型先输出推理文本，JSON被截断。`json_mode` 部分有效但不稳定。

### 4.3 改进方向

- 换用支持 `response_format` 更好的模型（如 deepseek-v3）
- 或在校验prompt中添加"不要思考，直接输出JSON"
- 或接受当前40%成功率，校验作为可选增强而非必需

## 五、结论

### 5.1 v3优化效果

| 维度 | 评价 |
|------|------|
| 污染消除 | ★★★★★ 完全消除 |
| 条数控制 | ★★★★ 从35.9降到20.8，更精准 |
| 耗时优化 | ★★★★ 从24.73s降到12.33s |
| 校验机制 | ★★★ 40%成功率，有总比无好 |
| 检索质量 | ★★★★ 高分场景8-9/10 |

### 5.2 混合检索策略建议

```
被动检索（2-3s）──────→ 基础结果集
                        │
主动检索（10-12s）──→ 小模型思考 → 并行3组检索 → 去重 → 校验
                        │
                        └──→ 合并去重 → 最终上下文
```

- **被动检索始终执行**：快、稳、无遗漏
- **主动检索并行执行**：联想广、覆盖全
- **合并时主动结果追加到被动结果后面**
- **主动检索超时或失败不影响被动结果**

### 5.3 进入分支开发的条件

| 条件 | 状态 |
|------|------|
| 污染消除 | ✅ 已验证 |
| 条数可控 | ✅ 平均20条，上限30 |
| 耗时可接受 | ⚠️ 12s偏高，并行后主循环可接受 |
| 校验有效 | ⚠️ 40%成功率，需进一步优化 |
| 检索范围完整 | ✅ 包含近期摘要+L1+玩家输入 |

**建议**：可以进入 `feature/parallel-thinking-retrieval` 分支开发，将主动检索与DC判断并行。校验机制作为可选模块，初期不强制要求。
