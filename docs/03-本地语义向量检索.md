# 本地语义向量检索详解（semantic_index.py）

本地语义向量检索是世界书引擎的 **L5 语义层**：用本地运行的中文 embedding 模型把「查询文本」和「世界书条目」都编码成向量，通过余弦相似度找语义相关（而非字面相同）的条目。

没有这一层，检索只能靠字面匹配——搜索「辽东大侠」找不到「胡一刀」；有了这一层，绰号、描述、同义改写都能命中。

---

## 1. 工作原理

```
世界书2218条目 ──embedding模型──→ 向量矩阵 [2218, 512]（归一化，缓存到磁盘）
                                          │
玩家输入+上轮剧情 ──embedding模型──→ 查询向量 [512]
                                          │
                            矩阵乘法 = 余弦相似度 [2218]
                                          │
                          Top30 → 过滤相似度<0.45 → 计分（sim×2.0）交给世界书
```

- **模型**：`BAAI/bge-small-zh-v1.5`（默认），中文小模型，512 维，体积约 95MB，CPU 即可运行（无 GPU 要求）
- **相似度**：向量已归一化，内积即余弦相似度，一次矩阵乘法完成全部比对
- **打分**：命中条目按 `相似度 × 2.0 × 条目权重` 计入世界书总分，与 L1~L4 关键词得分累加排序

## 2. 三个配置项（.env）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `ENABLE_SEMANTIC_SEARCH` | false | 总开关；`true` 才启用 |
| `SEMANTIC_MODEL` | BAAI/bge-small-zh-v1.5 | 模型名，可换任意 sentence-transformers 支持的中文模型 |
| `SEMANTIC_MIN_SIMILARITY` | 0.45 | 相似度门槛，低于此分的命中被丢弃 |
| `SEMANTIC_SCORE_WEIGHT` | 2.0 | L5 打分系数，越大语义命中越容易进结果 |

## 3. 向量缓存与增量更新

向量编码是最耗时的环节（2218 条全量约 30 秒），因此设计了磁盘缓存 + 增量机制：

**缓存文件**（位于 `data/`，已被 .gitignore 忽略）：

- `semantic_vectors.npy` —— 向量矩阵（约 4.5MB）
- `semantic_ids.json` —— `[[条目ID, 内容哈希], ...]`，哈希用于检测条目内容变更

**增量策略**（`build_vectors()` 在世界书每次建索引时自动调用）：

1. 无缓存 → 全量编码
2. 有缓存时对比「当前条目集」与「缓存条目集」：
   - 新增条目 → 编码后追加
   - 内容哈希变化 → 删旧向量、重新编码
   - 已删除条目 → 移除对应向量行
   - 无任何变化 → 直接用缓存（后台预加载模型）
3. 变动量超过 50% → 放弃增量，全量重建更划算

因此修改世界书数据文件后**无需全量重编码**，只有新增/变更的条目需要编码。

## 4. 部署与预构建

### 4.1 安装依赖

```bash
pip install sentence-transformers numpy
```

> 这会附带安装 torch（CPU 版），体积较大。不装也不影响游戏运行——自动降级为纯关键词检索（L1~L4）。

### 4.2 预构建索引（推荐）

```bash
python build_semantic_index.py             # 构建/增量更新
python build_semantic_index.py --rebuild   # 强制全量重建
```

为什么预构建：游戏运行中首次触发检索才编码的话，玩家会卡 30 秒~2 分钟；预构建后游戏启动直接加载缓存，检索零等待。

首次运行细节：

- 需联网下载模型（约 95MB，已内置国内镜像 `hf-mirror.com` 加速）
- 全量编码约 1~3 分钟（视 CPU 而定）
- 模型和缓存都落地后，**之后完全离线可用**

### 4.3 启用

`.env` 中：

```ini
ENABLE_SEMANTIC_SEARCH=true
```

## 5. 安全降级链

该模块的设计是「永远不拖垮游戏」：

| 情况 | 行为 |
|------|------|
| `ENABLE_SEMANTIC_SEARCH=false` | 不加载，世界书走纯关键词 |
| sentence-transformers 未安装 | 加载失败静默降级，不报错 |
| 模型加载异常（内存不足等） | 打印警告后降级 |
| 检索时异常 | 返回空列表，世界书照常返回关键词结果 |
| 缓存文件损坏 | 忽略缓存，重新构建 |

## 6. 性能参考（CPU 实测）

| 环节 | 耗时 |
|------|------|
| 模型加载（有缓存） | 约 3~10 秒，游戏启动后台完成 |
| 全量编码 2218 条 | 约 30 秒（一次性，之后走缓存） |
| 单次查询编码+比对 | 约 50~100ms |
| 内存占用 | 模型约 500MB + 向量矩阵 4.5MB |

## 7. 与云端记忆的区别

| | 本地语义检索（本模块） | 云端记忆（cloud_memory_v2.py） |
|--|--|--|
| 检索对象 | **静态世界设定**（NPC/武功/门派等 2218 条） | **动态游戏历史**（玩家经历的剧情、NPC 记忆） |
| 运行位置 | 本地 CPU | 阿里云百炼 API |
| 费用 | 免费 | 按量计费（可选功能） |
| 依赖 | sentence-transformers | DASHSCOPE_API_KEY |

两者互补：本地语义检索让 AI「懂世界设定」，云端记忆让 AI「记得你做过的事」。
