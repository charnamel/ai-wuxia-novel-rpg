# 游戏模块详解

本文档按功能域介绍项目的每一个代码模块：职责、核心机制、数据文件与模块间协作。

```
                         ┌────────────┐
        浏览器/手机  ───→ │ web_server │ Flask API + 前端
                         └─────┬──────┘
                               │
                         ┌─────▼──────┐
                         │   main.py  │ 主循环：剧情生成/状态解析/记忆管理
                         └─┬──┬──┬──┬─┘
              ┌────────────┘  │  │  └──────────────┐
        ┌─────▼─────┐  ┌──────▼──────┐  ┌──────────▼─────────┐
        │dice_system│  │battle_system│  │ player_manager 等  │
        │ 骰子检定   │  │ 回合制战斗  │  │ 玩家/任务/装备/修炼 │
        └───────────┘  └─────────────┘  └────────────────────┘
              │                                 │
        ┌─────▼──────────┐            ┌────────▼─────────┐
        │ worldbook 语义  │            │ cloud_memory_v2  │
        │ (静态世界知识)  │            │ (云端剧情记忆)    │
        └────────────────┘            └──────────────────┘
```

## 一、程序入口与 Web 服务

### run.py — 启动入口

设置工作目录为脚本所在目录后启动 Flask 应用，监听 `0.0.0.0:5000`（本机和局域网均可访问）。服务器部署时通过 `run:app` 交给 gunicorn。

### web_server.py — Web 服务层（约 200KB）

提供全部 HTTP API 与页面路由，是前后端唯一桥梁：

- **剧情接口**：接收玩家输入 → 调用 main.py 的 `process_one_round()` → 流式返回 AI 剧情
- **可视化编辑器**（仿「角色属性编辑器」风格）：玩家属性、武功、物品的网页编辑
- **弹窗系统**：任务面板、NPC 档案、武功书均以弹窗形式呈现
- **地图系统**：世界地图展示与玩家驱动的地点选择（选择后注入剧情生成上下文）
- **战斗模块**：Web 端触发战斗、逐回合出招、骰子检定确认面板
- **管理功能**：云记忆槽位等配置的在线修改

Web 端与 CLI 端共用同一套核心逻辑（`process_one_round(is_web=True/False)`），两种玩法行为一致。

## 二、主循环（main.py）

整个游戏的心脏，约 300KB，负责一轮交互的完整生命周期。

### 每轮流程（process_one_round）

1. **输入预处理**：区分【玩家场景/心理描述】与【玩家台词】两类输入标签，保留原文注入
2. **上下文组装**（见下文多层记忆）
3. **世界书检索**：用「上轮剧情+本轮输入」检索静态世界知识注入（详见 [02-世界书引擎.md](02-世界书引擎.md)）
4. **LLM 调用**：主循环模型生成剧情（支持工具调用）
5. **工具调用解析**：解析 AI 返回的 tool_calls 更新游戏状态（`parse_tool_calls_to_update_data`）
6. **状态提取**：辅助模型/工具更新玩家状态与 NPC 状态
7. **记忆更新**：更新上下文缓存（L2 的 50 轮累加窗口写入本轮记录）、按轮数周期触发 L2/L3 后台生成、上传云端记忆

### 多层记忆系统（上下文缓存）

**每轮实际注入 AI 的记忆由三层构成：50 轮累加细节 + 最新 2 章概要 + 全局脉络（100 轮一更新）**，外加即时锚点与云端召回。真实注入结构（main.py 构建 dynamic_info）：

```
【*L3-1 全局剧情脉络*】          ← 全脉络：full_plot_summary，每100轮更新
・1-{last_l3_gen_round}章剧情脉络：{全量剧情概要}
・人物关系：当前身份 / 当前盟友 / 当前敌人

【*L3-2 近期概要*】              ← 最新2章：chapter_summaries[-2:]
・最新2章概要：{第X-1章 + 第X章}

【*L2 最近50轮细节 · 细节参考*】  ← 50轮累加窗口：{cache_window}

─────────────────────────        ← 关键位置分隔线，防长文本后AI注意力滑过

【*L1 即时场景锚点 · 剧情承接*】  ← 上一轮剧情结尾约250字：{last_log}
```

| 注入层 | 内容 | 更新周期 |
|--------|------|---------|
| L1 即时场景锚点 | 上一轮【本轮剧情】结尾 250 字（刻意排除【玩家行动】头，避免 AI 复制而非响应新行动） | 每轮实时 |
| L2 最近50轮细节 | 当前 50 轮区块内全部逐轮记录的累加 | 每轮累加，跨块重置 |
| L3-2 近期概要 | 最新 2 章章回式摘要（每章 300~400 字） | 每 50 轮生成一章 |
| L3-1 全局剧情脉络 | 「1-X章剧情脉络」全量摘要 + 人物关系（X=最后生成截至轮数） | **每 100 轮**更新（第 101/201/301…轮） |
| L4 云端召回 | NPC 个人记忆 + 历史剧情线索（章节/剧情轮/任务/剧情记录四通道检索） | 每轮按需检索注入 |

#### L2 的「50轮累加」窗口——缓存友好设计

```python
# main.py：缓存友好窗口
total = len(interact_logs)
block_start = (total - 1) // 50 * 50          # 当前50轮区块的起始下标
cache_window = "\n\n".join(interact_logs[block_start:-1])
```

交互日志按 **50 轮一块**划分：区块内每新增一轮，窗口在原内容后**累加**一条（前缀不变）；跨入新区块时窗口**重置**，从新块起点重新累加。这样设计是为了**最大化 DeepSeek 等厂商的前缀缓存（Prompt Cache）命中**——块内每轮请求的上下文前缀完全一致，命中缓存的 token 按缓存价计费（通常为原价的一至五折），长剧情下 API 成本大幅下降。跨块重置则控制窗口不超过 50 轮，防止上下文无限膨胀。

#### 各层生成时机（后台线程异步）

| 记忆层 | 触发条件 | 生成方式 |
|--------|---------|---------|
| L2 章节摘要 | 第 50/100/150…轮 | 取最近 100 轮日志为素材，生成 1 章 300~400 字摘要（章回式小标题+正文），后台线程执行；生成期间上锁阻止下一轮开始，写完后解锁 |
| L3 全量脉络 | 第 101/201/301…轮（特意错开 L2 一轮，确保章节已写入缓存） | 旧全量摘要为底 + 最近 2 章增量融合（新章节优先），后台线程执行 |
| last_plot_summary | 每 20 轮 | 内部缓存字段（角色锚点+远古核心剧情提要+最近3轮精简），供系统内部取用，**不注入 AI 上下文** |

**玩家手动调整**（进阶玩法）：记忆层的触发轮数标记保存在 `data/context_cache.json`，可直接用文本编辑器修改：

- `last_l2_gen_round` / `last_l3_gen_round` —— 触发标记。改成小于当前轮数的值（或 0）即可在下一轮**强制重新生成**对应记忆层；想延后生成可改大
- `chapter_summaries`、`full_plot_summary` 等摘要字段 —— 内容本身可直接编辑，例如手动精简过长的全局脉络进一步节省 token，或修正 AI 摘要中的错误设定

配套机制：

- **同轮防重复**：L2/L3 触发前先检查 `last_*_gen_round` 占坑标记，线程启动前先写入，杜绝同轮重复生成
- **历史归档**：每 200 轮生成一份 history_archive 快照（章节摘要+大事记+传记+最近对话，保留 100 份）；每 5000 轮将旧交互日志移出（保留最近 2000 轮，归档保留 50 份），`query_history()` 支持回溯查询
- **上下文长度监控**：超过 25000 字打印警告，维持 AI 注意力
- **NPC 记忆蒸馏**：`_distill_npc_memories` 把 faction_balance 中的「姓名|记忆」按 NPC 归档，防止记忆张冠李戴

### 状态提取（工具调用）

AI 每轮可通过 function calling 更新游戏状态，主要工具：

| 工具 | 作用 |
|------|------|
| `update_player_state` | 物品增减、状态变化、境界提升、新剧情原子记录（new_rumor）、武功经验 |
| `npc_favor_update` | NPC 好感变化（单次 ±1~±8，需实质互动，闲聊不触发） |
| NPC 记忆/技能/身体状态 | NPC 档案的动态更新 |

`new_rumor`（主线剧情原子记录）：玩家本轮实际经历的关键事件，30 字内，NPC 有可能通过传闻/目击/当事人转述等渠道得知——AI 用它发展剧情，但不代表所有 NPC 自动知晓（信息隔离设计）。

### 世界状态

每轮维护 `world_trend`（江湖大势 30 字）、`faction_balance`（本轮 NPC 记忆：`姓名|记忆内容` 多条）、玩家情绪等，随剧情动态演化；死亡 NPC 列表单独注入，防止已故角色再出场。

## 三、骰子检定系统（dice_system.py）

D&D 风格的 d20 检定，是「武功是否生效、动作是否成功」的判定核心。

### 检定流程

```
玩家输入 → 检测武功 → AI 判定 DC → 掷 d20+修正 → 对照 DC 出结果档位 → 生成约束文本注入剧情
```

1. **武功检测**（`detect_martial_skill`）优先级：
   ① 精确/模糊名词匹配（输入中完整出现武功名）
   ② 类型匹配（「运起内力」「施展轻功」等类型词）→ **装备槽已学的内功/轻功优先**
   ③ 装备槽为空时 → 选 exp 最高的该类型武功
   ④ 兜底：装备槽武功
2. **DC 判定**（`ai_judge_dc_only`）：辅助模型根据场景上下文判定难度等级，首轮战斗用战斗前剧情末 500 字，后续轮次用上一轮剧情；DC 限制在合理区间
3. **掷骰与档位**（`judge_grade_v4`）：`d20 + 修正` 对照 DC，八档结果：大成功 → 成功 → …… → 大失败；**天然 20 必成功、天然 1 必失败**；结果侧重叙事丰富性而非机械成败
4. **修正来源**：整体境界基础修正（初学 -1 → 破碎虚空 +12，共 14 档）+ 武功自身境界加成（2 境一档：0/+1/+2/+3/+4/+5/+6/+7，适配瓶颈突破即晋档）+ 增幅加成
5. **增幅系统**（`compute_amplify_bonus`）：内功/轻功催动攻击时按武功品阶提供额外加成
6. **特效触发**（`compute_effect_trigger`）：高品阶武功有几率触发特殊效果（martial_effects.json 定义）

规则数据外置于 `data/dice_rules.json`（检定规则）与 `data/martial_effects.json`（特效表），支持热重载。

### 约束文本

检定结果生成「约束文本」（`build_constraint_text_v4`）注入剧情生成——AI 必须按骰子结果叙事，防止 AI 自说自话绕过判定。

## 四、回合制战斗系统（battle_system.py）

与 NPC 的独立对战模式，AI 承接打斗叙事：

- `run_battle_system`：战斗主流程，逐回合进行
- `gen_single_battle_round`：生成单回合打斗（玩家出招文本 + 骰子约束 + 战场状态 → AI 叙事）
- `ai_check_battle_status` / `ai_judge_battle_trend`：AI 判定战斗是否结束、当前战局优劣
- `gen_battle_final_end`：生成战斗终局描述

战斗中每回合出招同样走骰子检定（武功检测逻辑与剧情模式一致），战斗上下文与主线剧情隔离缓存（`clear_battle_cache` / `get_last_battle_context`），战斗结束后关键结果回流主线。

## 六、剧情演化与任务

### mainline_dynamic.py — 主线动态演化

管理 89 个原著主线桥段的严格顺序推进，核心铁律：**核心事件、关键人物、剧情内核 100% 遵循原著，AI 只负责把「触发入口」适配到玩家当前场景**（通过听闻、说书、偶遇等方式无缝衔接，不许瞬移）：

- **桥段目录**：`data/mainline_catalog.json`，每条含 `id`（顺序号）、`title`、`summary`（核心剧情）、`year`（年代，禁止提前出现未来人物）、`original_plot`（原著出处）、`involved_npcs`、`trigger_hint`（触发方式提示）
- **两种触发路径**：
  - 手动：指令「回归主线」→ `advance_mainline()`，前置校验不通过时零 API 消耗直接返回
  - 自动：剧情进度积分制——普通行动每轮 +1、战斗结算 +5、手动「回归主线」+8，累计满固定阈值 100（`MAJOR_PLOT_TRIGGER_POINT`，触发后 `current_progress` 归零重新累计）后设置标志，下一轮自动注入「主线暗线牵引」：只读取下一桥段（当前进度 X+1）的标题/概要/涉及人物，引导 AI 在当前场景自然埋下线索，**不推进主线编号、不自动建任务**
- **状态持久化**：`data/mainline_history.json`（events 已发生事件 / current_order / last_trigger_round 触发轮次 / manual_skip_id 跳转目标）
- **生成保障**：LLM 输出经三层 JSON 解析兜底，关键字段（标题/摘要/涉及人物）强制对齐目录桥段，解析失败也绝不偏离原著

### task_manager.py — 任务系统

主线之外的支线任务管理，Web 端弹窗操作：

- 任务 CRUD：创建/完成/删除/暂停
- 进度更新：阶段描述 + 百分比，AI 每轮可通过 `parse_ai_task_updates` 自动更新任务进度
- 任务简介注入 AI 上下文（`get_task_brief_for_ai`），让 AI 记得玩家的进行中事项
- 关键节点上传云端记忆（`upload_task_memory`）

### 主线操作演示（生成 → 完成 → 跳转 → 任务窗口控制）

主线控制的全部入口在 Web 界面快捷按钮区（输入框上方一排按钮）：

```
[回归主线]  [❓当前主线]  [✅主线完成]  [📖选择主线（跳转主线 N）]  ...  [📜任务]
```

#### ① 生成主线——「回归主线」

点击「回归主线」（或直接输入指令 `回归主线`）。触发前有两道前置校验，**不通过时直接返回提示、不消耗 API**：

- 校验 1：仍有进行中（pending）的主线事件 → 拒绝，提示先完成当前剧情再开新主线
- 校验 2：距上次触发不足 3 轮 → 冷却，提示还需推进几轮剧情

校验通过后，系统取目录中下一个桥段，AI 只设计「触发入口」把事件接到你当前的场景。触发后事件涉及的 NPC 被强制注入本轮活跃 NPC 集合，保证人设一致。

不点按钮也会自动触发：进度累计满 100 分即触发一次（普通行动每轮 +1、战斗 +5）。触发时系统自动取「当前进度 X+1 号桥段」，注入【主线暗线牵引】，在**当前剧情流里自然埋一枚指向下一段桥段的线索**（异常动静/密信/故人提点/流言一角）——不切换场景、不移动主线进度编号、不自动建任务，真正的展开待玩家主动靠近后再继续。玩家主动推进到第 X+1 号后，自动触发才顺延指向第 X+2 号。

#### ② 查看状态——「当前主线」

点击「当前主线」查看进行中的事件全貌：核心剧情、触发入口、涉及人物、原著出处，以及原著总进度（第 X / 89 桥段）和下一桥段预告。

#### ③ 完成主线——「主线完成」

剧情演完一个桥段后点击「主线完成」，最近的 pending 事件被标记为 completed，之后才能触发下一条主线。这就是主线推进的完整循环：**回归主线 → 游玩 → 主线完成 → 回归主线**。

#### ④ 跳转主线——「选择主线」+「跳转主线 N」

想跳过不感兴趣的桥段、或重玩某段时：

1. 点击「选择主线」查看即将到来的主线清单（当前进度 + 后 5 个桥段的编号/年代/标题/概要）
2. 在输入框输入 `跳转主线 编号`（如 `跳转主线 5`），系统校验编号范围（1~89）后设置跳转标记
3. 再次点击「回归主线」时直接从目标桥段继续（跳转标记随即清除，恢复顺序推进）

#### ⑤ 任务窗口控制主线

点击「📜 任务」打开任务管理弹窗（与 NPC 编辑、武功书同款弹窗风格）。任务卡片分 **⭐主线 / ○支线** 两类，对主线的控制手段：

- **「切换」按钮**：把任意任务在主线/支线间一键转换——把 AI 生成的支线任务升级为主线标记后，AI 会按主线任务的严格规则对待它（进度必须与剧情严格匹配、日常闲聊不更新、推进到 75% 时自然收尾）
- **进度行**：每张任务卡片有阶段描述 + 百分比两个输入框，可手动校正 AI 的进度判断（📤 提交）
- **「完成」按钮**：任务完成后自动生成剧情总结并上传云端记忆（`upload_task_memory`），AI 长期记得此事
- **「搁置 / 激活」**：暂时挂起某个任务（不再注入 AI 上下文）或重新激活
- 任务简报每轮注入 AI 上下文（`get_task_brief_for_ai`），AI 由此知道玩家手上有哪些未了之事

#### 完整案例：从第 2 桥段开始的一段主线游玩

背景：玩家创建角色后在辽东一带游历，主线进度停在 1 号桥段「闯王兵败九宫山」（已完成）。

**第 1 步 · 触发主线**

点击「回归主线」。系统取到下一个桥段——2 号「飞天狐狸投吴三桂」（1645 年，出自《雪山飞狐》第四回回忆）。AI 结合玩家当前所在（辽东小镇客栈）生成触发入口，剧情大致如下：

> 你在客栈用饭，邻桌一名老者抿着酒，忽然长叹一声："当年闯王兵败，胡家的飞天狐狸投了平西王吴三桂，出卖闯王行踪换富贵……天下人提起这名字，谁不唾骂一句叛徒！"你心中一动——江湖传闻闯王宝藏与胡家百年恩怨，正始于此。

注意：核心剧情（飞天狐狸投吴三桂、忍辱负重）是原著定死的，AI 只是把「听老者说起」这个入口安在了客栈场景。若玩家 3 轮内刚触发过主线，此时会收到「江湖大事非朝夕可至，还需推进 X 轮剧情」的冷却提示。

**第 2 步 · 游玩推进**

玩家围绕此事游玩数轮：追问老者详情、去查访知情者、卷入苗范田三家后人的冲突……每轮正常剧情都在积累进度分；任务面板里相关任务（AI 自动创建或玩家手动新建，如「查证飞天狐狸叛变真相」）的百分比随剧情推进被 AI 逐步更新。

**第 3 步 · 完成主线**

剧情告一段落（查清了飞天狐狸投敌的表象，但真相成谜——正是原著留的扣子），点击「主线完成」：

> ✅ 主线事件已标记为完成，主线剧情将继续推进。

此时 `mainline_history.json` 中该事件 status 变为 completed，进度定格在第 2 桥段。

**第 4 步 · 跳转主线（可选）**

玩家不想按顺序走 3 号「三家追杀飞天狐狸」，想直接跳到更感兴趣的鸳鸯刀剧情：

1. 点击「选择主线」，看到清单：

   ```
   📖 即将到来的主线（当前进度：第2号）：
     3. [1646] 三家追杀飞天狐狸 — 苗范田三家不明真相，愤而联手追杀飞天狐狸……
     4. [1720] 鸳鸯宝刀传说 — 雍正即位初年，江湖渐传一对鸳鸯宝刀藏有'无敌于天下'的大秘密……
     5. [1722] 萧义净身入宫 — 雍正二年，三湘大侠萧义为报袁杨两家灭门之仇……
   ```

2. 输入 `跳转主线 4`，系统回复：

   > ✅ 已跳转到第4号（1720年）「鸳鸯宝刀传说」，下次「回归主线」生效

**第 5 步 · 任务窗口收尾控制**

打开「📜 任务」弹窗，把游玩中累积的支线任务整理一遍：将「查证飞天狐狸叛变真相」点「切换」升级为 ⭐主线标记（它的后续进展将按主线规则严格推进）；已无关的旧任务点「完成」或「搁置」。下一次「回归主线」即从第 4 桥段「鸳鸯宝刀传说」继续。

**提示**：跳转只影响「下一个取哪个桥段」，不会补生成被跳过桥段的剧情；跳到低编号桥段可重玩该段（原事件历史仍在，但新事件按跳转目标生成）。

## 七、记忆与检索

### worldbook.py — 世界书引擎

静态世界知识检索（2218 条目/六大数据源/L1~L5 五层检索），详见 **[02-世界书引擎.md](02-世界书引擎.md)**。

### semantic_index.py — 本地语义向量检索

世界书的 L5 语义层（本地 embedding 模型 + 向量缓存 + 增量更新），详见 **[03-本地语义向量检索.md](03-本地语义向量检索.md)**。

### cloud_memory_v2.py — 云端长期记忆（可选）

基于阿里云百炼记忆 API 的动态剧情记忆，解决「长剧情 AI 遗忘」：

- **上传通道**（每轮自动触发）：逐轮剧情（`upload_plot_memory`）、章节摘要、重要记忆（评分≥阈值）、NPC 记忆、任务节点、剧情原子记录——全部携带 novel_node 时间戳标记
- **检索单元**：`build_compact_context` 按需拉取与当前剧情相关的历史记忆注入上下文
- **工程保障**：线程安全 LRU 缓存 + 上传去重器（unique_id 幂等）+ 失败静默降级（云端不可用不影响游戏）
- 未配置密钥时全部功能自动关闭，纯本地记忆照常游玩

## 八、世界运行时与工具

### location_time.py — 地点时辰

维护当前地点、时辰（十二时辰制 + 24 小时换算）、天气；`advance_world_time` 按剧情节奏推进时间，注入每轮 L1 场景锚点。

### image_generator.py — AI 配图（可选）

`draw_ascii`：按最新剧情生成配图提示词 → LLM 生成提示词 → 调图片接口出图，带本地缓存（`static/images/plot_cache/`）；未配置时降级为文字描述。

### save_manager.py — 存档管理

多槽位存档（`data/game_save.json` + 归档目录），`list_saves` / `save_game` / `load_game` / `delete_save` 完整 CRUD。

### file_utils.py — 文件工具

JSON 安全读写、交互日志（`interact_log.jsonl` 追加/重写）、上下文缓存持久化。

### llm_utils.py — LLM 工具

`get_llm_content`：兼容新旧格式的 LLM 返回值内容提取。

### config.py — 配置中心

全部密钥与 API 配置从 `.env` 环境变量读取（密钥与代码彻底分离）；支持主循环/辅助/配图三组模型多方案热切换（`*_ACTIVE` 环境变量选择）。
