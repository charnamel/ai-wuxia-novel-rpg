## 二、关键发现

### 2.1 主动检索的优势

**（1）联想扩展能力强**

场景2（Round 245）最佳体现：玩家问"铁寨主叫什么名字，擅长什么武功"，被动检索只找到8条。主动检索生成了5组维度：
- [人物] 铁雄 铁门寨 寨主
- [武功] 铁门闩刀法 铁雄 刀法
- [地点] 铁门寨 川境 缉捕营
- [剧情线索] 袁依依 马行空 镖箱 追镖
- [剧情线索] 铁雄 官府 把总 背景

多找到了20条，包括铁雄的武功详情、铁门寨位置、相关任务记录等，对AI演绎剧情非常有帮助。

**（2）云向量库命中率高（XSFH6）**

XSFH6向量库表现优秀，几乎每个场景都有相关记忆命中：
- 霍青桐场景：score=0.832（叶尔羌河记忆）
- 鸳鸯刀场景：score=0.891（林玉龙记忆）
- 赵天鸿场景：score=0.852（陆菲青记忆）
- 春花师姐场景：score=0.891（马春花记忆）

这些记忆直接复现了玩家当时的台词和场景，对保持剧情连续性极有价值。

**（3）短文本场景优势明显**

场景6（"师父，当然是……报官咯"）仅7个字，被动检索只找到1条。主动检索联想出"报官 告状 缉捕"等关键词，找到24条。对于短文本输入，主动检索的价值最大。

### 2.2 主动检索的问题

**（1）剧情节点污染（严重）**

这是最大的问题。当前剧情节点"1753年夏，晋阳城外铁鹞堂布围，萧半和病危"被注入了思考prompt，导致小模型在几乎每个场景都生成 `[剧情线索] 萧半和 病危 铁鹞堂` 的检索组——即使完全无关：

| 场景 | 是否生成"萧半和/铁鹞堂" | 相关性 |
|------|------------------------|--------|
| Round 1（开局报名） | ✅ 是 | ❌ 无关 |
| Round 686（不想走镖） | ✅ 是 | ❌ 无关 |
| Round 932（霍青桐出发） | ✅ 是 | ❌ 无关 |
| Round 1176（报官） | ✅ 是 | ❌ 无关 |
| Round 1421（春花闲聊） | ✅ 是 | ❌ 无关 |
| Round 1666（赵天鸿作证） | ✅ 是 | ❌ 无关 |
| Round 1911（杭州分号） | ✅ 是 | ❌ 无关 |
| Round 2155（陈家洛就任） | ✅ 是 | ❌ 无关 |

10个场景中有8个被污染，平均每场景增加约14条无关结果。

**（2）二次校验失效**

所有场景的校验结果都是 `score=0, 未校验`。原因是校验JSON解析逻辑有bug——模型返回的JSON中包含嵌套的花括号，`re.search(r'\{[^}]+\}')` 正则无法正确匹配。

**（3）重复结果未去重**

场景10（陈家洛就任）中，"陈家洛 红花会 总舵主"和"于万亭 红花会 总舵主"和"红花会 十四当家 二当家 派系"三组都命中了红花会相关条目，大量重复，实际有效信息远少于87条。

**（4）耗时过高**

主动检索平均24.73s，是被动检索的9倍。原因：
- 小模型思考：3-7s
- 5组检索串行执行：每组3-4s，共15-20s
- 二次校验：3-5s

对于实时游戏，这个延迟不可接受。

## 三、优化方案

### 3.1 去除剧情节点污染

**方案**：从思考prompt中移除 `novel_node` 字段，或改为"仅在玩家输入与主线相关时才提示"。

```
# 修改前
【主角状态】
姓名：李三奇 / 境界：渐入佳境 / 剧情节点：1753年夏，晋阳城外铁鹞堂布围，萧半和病危

# 修改后
【主角状态】
姓名：李三奇 / 境界：渐入佳境
```

**预期效果**：消除80%的污染场景，主动检索条数从35.9降到约22条（有效信息不减少）。

### 3.2 限制检索组数 + 并行执行

**方案**：
1. 将最大检索组数从5降到3（2组聚焦 + 1组扩展）
2. 使用 `concurrent.futures.ThreadPoolExecutor` 并行执行多组检索

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def execute_retrieve_multi_parallel(query_groups, sources):
    results = {}
    with ThreadPoolExecutor(max_workers=3) as executor:
        futures = {
            executor.submit(execute_retrieve_single, g["query"], sources): g
            for g in query_groups
        }
        for future in as_completed(futures):
            group = futures[future]
            results[group["dimension"]] = future.result()
    return results
```

**预期效果**：5组串行15-20s → 3组并行3-4s，总耗时从24.73s降到约10s。

### 3.3 修复二次校验

**方案**：使用更健壮的JSON提取逻辑：

```python
# 修改前
json_match = re.search(r'\{[^}]+\}', verify_text)

# 修改后
json_match = re.search(r'\{.*\}', verify_text, re.DOTALL)
```

### 3.4 添加去重逻辑

**方案**：对世界书检索结果按条目标题去重：

```python
def deduplicate_worldbook(results_text):
    seen = set()
    deduped = []
    for line in results_text.split("\n"):
        title = line.strip()[:20]  # 用前20字作为去重键
        if title and title not in seen:
            seen.add(title)
            deduped.append(line)
    return "\n".join(deduped)
```

### 3.5 混合检索策略（最终方案）

```
玩家输入
    │
    ├──→ 被动检索（直接用玩家输入，2-3s）
    │         │
    │         └──→ 基础结果集
    │
    ├──→ 主动检索（小模型生成关键词，并行，~10s）
    │         │
    │         ├──→ 多维度检索（3组，并行）
    │         ├──→ 去重
    │         └──→ 二次校验
    │
    └──→ 合并去重 → 最终上下文
```

**关键原则**：
- 被动检索始终执行（快、稳、无遗漏）
- 主动检索并行执行（慢、但联想广）
- 合并时主动检索的结果去重后追加到被动结果后面
- 如果主动检索超时或失败，不影响被动检索结果

## 五、结论与建议

### 5.1 主动检索值不值得做？

**值得**，但需要优化。核心价值在于：
1. 短文本输入的联想扩展（Round 1176：7字→24条）
2. 多维度覆盖（Round 245：从单一人物到武功/地点/剧情全覆盖）
3. 云向量库的主动调用（被动检索容易漏掉NPC记忆）

### 5.2 最大的风险是什么？

**剧情节点污染**。如果不修复，主动检索的每条结果中有30-50%是无关噪声，反而会降低AI的上下文质量。这是必须优先修复的问题。

### 5.3 实施优先级

| 优先级 | 优化项 | 预期效果 | 难度 |
|--------|--------|---------|------|
| P0 | 移除novel_node污染 | 消除80%噪声 | 低 |
| P0 | 修复二次校验JSON解析 | 启用质量过滤 | 低 |
| P1 | 并行执行检索组 | 耗时降至10s | 中 |
| P1 | 限制最大组数为3 | 减少噪声+加速 | 低 |
| P2 | 结果去重 | 减少冗余 | 中 |
| P2 | 混合策略合并 | 最终方案 | 中 |
