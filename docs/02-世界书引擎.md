# 世界书引擎

worldbook.py 管着游戏的静态知识库。内置两千多条武侠世界设定——人物、武功、门派、地点、物品、主线剧情。每轮生成剧情前，引擎根据最近的对话内容，把相关条目捞出来注入上下文。

简单说就是让 AI 上场前先翻一遍"资料卡"：剧情里提到苗人凤，苗人凤的档案就跟着进上下文，AI 不会把他写成另一个人。反过来，不相干的设定不塞进去，省 token 也不分散注意力。

## 收录了什么

六类数据，都在 `data/` 目录下：

- 主线剧情 89 条（mainline_catalog.json）
- NPC 档案 276 份（npc_agents.json）
- 武功 665 门，只收高品阶的（martial_arts_bonus.json）
- 物品 870 件（items_catalog.json）
- 门派 43 个（timeline_reference.json）
- 地点 275 处（map_data.json）

## 怎么检索

每轮的检索词是上一轮剧情加上玩家这轮的输入。打分大致分几层：

- 名字直接命中（比如输入里出现了"苗人凤"三个字）分数最高
- 关键词命中次之，每个条目都配了关键词
- 模糊匹配兜底，中文按两三个字的片段比对。物品类权重压得很低——八百多件物品，不压着太容易刷屏
- 年代对的条目加权，剧情走到哪一年，那年的事更容易被想起
- 装了语义检索的话，还有一层向量相似度匹配，"辽东大侠"也能找到胡一刀

打完分排序，每类限制条数和字数，最后拼成一段不超过两千字的资料注入给 AI。

整个检索在内存里完成，单次几毫秒。数据文件改了会自动重建索引，不用重启游戏。

## 想自己改世界书

直接编辑对应的 json 文件就行，比如给 npc_agents.json 加一个 NPC。格式照着已有条目抄：name 是主要检索依据，identity、personality、secret 拼成内容，keywords 数组可以主动补关键词。存盘后下一轮就生效。

开了语义检索的话，改完跑一遍 `python build_semantic_index.py` 更新向量，只有新增和改动的条目会重新编码，很快。

更细的打分规则和参数直接看代码，注释写得比较全。
